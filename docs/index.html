One Hub, Two Tools

Fabric Developer Hub is the umbrella platform. It bundles two complementary tools under one Fabric workload: Agent Hub for AI-agent orchestration, and Power BI Fixer for Power BI engineering. The previously standalone Power BI Fixer was merged into the Developer Hub and is now shipped as a first-class tool inside it.

Agent Hub Tool 1

An agent orchestration platform that runs as a native Fabric workload. Build, run, and govern AI agents that touch Lakehouses, Warehouses, Pipelines and Reports.

  • Skill-based composition model
  • Multi-agent orchestrator with plan review
  • Live streaming execution + HITL approvals
  • Workspace branching for safe experimentation
  • Microsoft Fabric workload (iframe + REST APIs)

Power BI Fixer Tool 2

Three-Step Orchestrator Workflow

From natural-language goal to deployed result — with full visibility and control at every stage.

1

Compose

Describe your goal in plain language and attach Fabric context.

  • NL prompt with autosuggestions
  • Lakehouses, warehouses, workspaces as context
  • Branching configuration
  • Approval requirements
2

Plan Review

Inspect and edit the AI-decomposed plan before launch.

  • Step list with agent + Fabric items
  • Approval gates on critical steps
  • Edit, reorder, reject steps
  • Cost & risk indicators
3

Execute (Streaming)

Watch agents work step-by-step with live reasoning and code output.

  • Streaming reasoning & code blocks
  • Approval cards mid-run
  • Artifacts linked back to workspace
  • Full audit trail

Example: Weekly Sales Ingestion

From natural-language goal to deployed pipeline in three steps.

# Goal (entered in Compose step):
"Automate the weekly ingestion of regional sales data from our
 OneLake raw zone, normalize the schema for Gold-layer reporting,
 and generate SQL-based views for the Finance dashboard."

# Context attached:
  Lakehouse:  corporate-sales-raw
  Warehouse:  Gold_Sales_DW
  Workspace:  Marketing Analytics
  Branch:     agent/sales-ingestion-pipeline

# Generated plan (5 steps):
  1. Discover Sources    → spark-consumption
  2. Resolve Schema     → sqldw-authoring
  3. Create Pipeline    → spark-authoring  [approval gate]
  4. Validate Output    → sqldw-consumption
  5. Generate Report    → powerbi-authoring

Getting Started

Run the full Developer Hub stack locally with Docker — backend, frontend and Fabric DevGateway.

# 1. Clone the repo
git clone https://github.com/LukaszObst/fabric_developer_hub.git
cd fabric_developer_hub

# 2. Configure environment
cd "Developer Hub"
cp .env.example .env  # fill in tenant, app, workspace IDs

# 3. Start the stack
docker compose up -d

# 4. Open Fabric and sideload via the dev-gateway
# Follow device-code prompt printed by dev-gateway logs
docker compose logs -f dev-gateway

Platform Notes

  • ARM64 hosts (Apple Silicon, Snapdragon): register QEMU emulation once with docker run --privileged --rm tonistiigi/binfmt --install amd64
  • Corporate VPN (Zscaler / GlobalProtect): pin Docker to the IANA benchmarking range (198.18.0.0/16) to avoid bridge subnet conflicts
  • AAD app: a multi-tenant app registration is required; the dev-gateway uses device-code flow on first start
  • Fabric Developer Mode: must be toggled on per browser profile in the Fabric admin portal
